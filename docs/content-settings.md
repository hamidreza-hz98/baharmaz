# Content settings

The singleton `contentsettings` document (MongoDB `_id` `site`) stores homepage banners, slogans and about copy; contact phone/social links, address and map URL; ordered FAQ and terms entries; about copy; and SEO title/description for the home, contact, FAQ, terms, about and product-list pages. Empty or partially populated records are projected onto complete empty defaults. No seed or migration is required; MongoDB's built-in `_id` index enforces the singleton. Back up the intended database before any manual migration. Revision starts at zero, and every successful save increments it; stale competing saves receive a conflict.

`GET /api/content` returns a deliberately constructed public projection and never returns revision, unknown database fields or credentials. It and the existing public shop introduction use no-store reads. `/` is dynamic and uses the first nonempty homepage slogan, with the existing Persian fallback when no slogan is set. When MongoDB is unavailable, reads return errors rather than presenting an outage as saved empty data. The separate `GET /api/admin/content` requires an admin session. `PUT /api/admin/content` requires the same session, a matching `APP_ORIGIN`, JSON and a complete `{ revision, content }` object obtained from the admin GET. Unknown fields, malformed IDs, oversized content, unsafe URLs and invalid/missing WebP media references are rejected. All fields are plain text; no HTML is trusted. Internal banner links must start with a single slash, while map/social links must be HTTPS without credentials. Ordered entries carry caller-supplied stable IDs, unique within their lists. Images referenced by public homepage or about settings are served through the restricted public image route; see `docs/information-pages.md`.

The mutation replaces the entire content projection atomically. Clients should retain unsaved edits and reload/resolve conflicts on HTTP 409. Successful writes invalidate `/`, `/contact`, `/faq`, `/terms`, `/about` and `/products`; dynamic/no-store reads also prevent stale public results. Body size is capped at 1 MiB. The public projection is not a place for passwords, API keys or provider credentials; these belong only in server configuration and must never be placed in the document. Unknown legacy fields are ignored on reads and removed by a successful full replacement. Direct database writes bypass validation and concurrency controls.

The protected `/admin/content` editor manages these fields, including image selection through the existing media library and keyboard-accessible ordering controls for repeated entries. It sends the complete document at the revision read on load. Save failures preserve the draft; after a conflict, fetching the latest version requires explicit confirmation because it discards the local draft. Browser unload also warns about unsaved changes. Changes are not merged automatically, so operators should copy important unsaved edits before reloading a conflicted version. The editor does not store credentials. The metadata preview, field checks and fallback rules are documented in `static-seo.md`.

`npm run test:integration` covers incomplete defaults, public projection, unsafe input, media references, authorization, conflicts, ordering, read-after-write and database restart against isolated MongoDB. The focused browser test covers image selection, ordering and conflict recovery on desktop and mobile. No provider or production secret is used.
