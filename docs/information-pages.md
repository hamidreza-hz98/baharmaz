# Homepage and information pages

The homepage uses saved banners (manual previous/next controls), slogans and about copy, ordered active categories and up to twelve recent promoted products. `/about`, `/contact`, `/faq` and `/terms` use the corresponding content settings and configured SEO title/description with Persian fallbacks. Native FAQ and terms disclosures support keyboard operation. Empty data is shown as an explicit empty state, not invented store policies. Existing shared loading and retryable error boundaries cover these pages. Configure content at `/admin/content` or through the protected API.

Only validated WebP images referenced by an active product, active category or published homepage/about settings are publicly available through `/api/catalog/media/[id]`; other media stays private. Public responses can be cached for up to 60 seconds after removal. Social and map links open configured HTTPS URLs; map content is not embedded and no tracking provider is contacted by the application.

## Contact setup and operations

Set `CONTACT_RATE_SECRET` to a unique random secret containing at least 32 UTF-8 bytes on every application instance. Keep it stable and outside source control. Set `APP_ORIGIN` to the site's actual origin. After backing up the intended database, run `npm run db:contact:indexes` with its database configuration; this creates a submissions listing index and the rate-bucket TTL index. The form fails closed if the secret or TTL index is missing. Changes to a secret reset per-mobile rate history; do not share it with third parties. No SMS, email, or external notification is sent: success means the message was stored in MongoDB for review.

The server accepts a name (2–120 characters), Iranian mobile number and message (5–4,000 characters), checks origin and body size, normalizes the mobile and stores plain text. A database-backed hourly global ceiling of 120 valid attempts and a limit of three per normalized mobile apply across instances, using HMAC identifiers and no untrusted client-IP headers. Fixed-window limits can allow bursts across an hour boundary, and the shared ceiling can affect legitimate users during abuse; operators should add a trusted edge rate limiter for larger deployments. Rate bucket TTL is cleanup only, not the enforcement mechanism. The protected `/admin/contact-submissions` page searches name, mobile or message and displays 20 entries per page, with a separate message dialog. The admin-only API supports `page`, `q` and exact `id` reads with no-store headers. Search is literal (regex characters are escaped), and message content is rendered as text. Access to raw contact data should be restricted and retention handled according to the shop's policy; no automatic message deletion is configured.

`npm run test:integration` uses isolated MongoDB for invalid requests, origin/authorization, limits, concurrent requests and persistence. For an additional desktop/mobile production-browser check, run `npm run build`, then set `MONGOD_BINARY` and `CATALOG_BROWSER_EXECUTABLE` before `npm run test:integration`. No live communications or production secrets are used.
