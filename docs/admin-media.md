# Admin media workflows

`/admin/media` and `/admin/media/upload` require an admin session and are excluded from indexing. The library reads the private GridFS metadata API, shows an image/video grid, searchable filename, type filter, page-level selection, metadata and preview. Selected filenames can be copied in bulk, with a manual-copy fallback. Preview failures and empty, no-result and request-error states are shown. The reusable `MediaPicker` supports selecting existing media or uploading a new file and then selecting it, with optional image/video restrictions. Future forms must validate the selected ID and permitted type on the server; the picker itself does not authorize a mutation.

The upload page supports file selection and drag-and-drop, up to ten files in the local queue. It uploads one file at a time. Progress is derived from the browser's `XMLHttpRequest.upload` events; where the browser cannot calculate progress, an indeterminate bar is shown. After transfer completes, the interface reports server processing and marks the item complete only after a successful persistence response. Failed or cancelled transfers can be retried or removed from the queue. Upload retries are **not idempotent**: if the connection is interrupted or the server fails after storing the bytes, a retry may create a duplicate. Check the library before retrying an uncertain upload. Removing an item from the local queue never deletes the stored file.

Deletion is deliberately unavailable, including for bulk selection. No delete endpoint or UI is provided because catalog/content references and historical usage are not yet tracked. This conservative policy protects both referenced and unreferenced files until a future task establishes reference checks and an explicit deletion workflow. The selection is limited to the current page and is cleared when filters or pages change.

The picker returns metadata and a media ID, not a public URL. Library access remains admin-private; validated images referenced by active public catalog or content can be retrieved through the separate public media route. Video container validation remains limited as described in `media.md`, and the earlier media-storage task remains open for full video-bitstream validation. Admin sign-in is available at `/admin/login`; tests use isolated sessions without real credentials. See `media.md` and `information-pages.md` for formats, access and orphan cleanup.

Run `npm run test:integration` for protected list/upload/retrieval and type-filter checks against isolated MongoDB. Run `npm run test:foundation` for desktop and mobile library, filter, preview, failure/retry, upload progress and picker behavior with mocked network responses. Browser progress tests exercise the real XHR event path but do not measure bandwidth or prove every network failure mode.
