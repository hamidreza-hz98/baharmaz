# Addresses, map and reverse geocoding

Customers manage addresses at `/account/addresses` after signing in. Every database read, edit and delete is scoped to the current customer; stale edits are rejected. Label, recipient, Iranian mobile and full address are required. Postal code is optional but must contain ten digits when present. Coordinates are optional as a pair of latitude and longitude so manual addresses remain possible when a provider is unavailable. Saved coordinates are WGS84 decimal degrees; the text address remains independently editable. The owner cannot be supplied by the client. Addresses are private personal data, returned with no-store headers and excluded from public pages and metadata.

Back up the intended database before setup and run `npm run db:address:indexes` using its configured environment. This creates an owner/listing index and does not delete data. No existing-data migration is needed. No default delivery area, shipping eligibility or location is implied by a saved address.

## Optional map provider

By default no tiles are requested and users can enter both address and coordinates manually. To enable Leaflet tiles, set `MAP_TILE_URL` to an approved HTTPS XYZ template containing `{z}`, `{x}` and `{y}`, and set `MAP_ATTRIBUTION` to the provider's required plain-text attribution. Both must be set. The tile template is sent to customer browsers: it must not contain private credentials. The map starts centered on Tehran only as a navigation starting point and does not save that location until the customer selects it. Users can also use the keyboard-accessible coordinate inputs. Opening the map is optional and sends tile requests and the customer's IP address to the configured tile provider. A tile-load failure gives a manual-entry message; close and reopen the map to retry.

Use a tile service whose terms, availability in the users' region, capacity, privacy and pricing have been checked for this deployment. Leaflet attribution must remain visible. The public OpenStreetMap tile server has its own [tile usage policy](https://operations.osmfoundation.org/policies/tiles/) and must not be treated as an unlimited production service. No default provider is selected or verified by this application.

## Optional reverse geocoder

Set server-only `GEOCODER_URL` to an approved HTTPS Nominatim-compatible reverse endpoint returning JSON `display_name`. It is not sent to the browser. Providers requiring secrets may use a server-side query parameter; do not include credentials in the tile URL. The application calls the geocoder only when the user explicitly requests a suggestion, transmitting the chosen coordinates. It limits the whole deployment to one lookup per second using a shared MongoDB record, disables redirects, bounds the response to 64 KiB and times out after five seconds. This global ceiling is not a substitute for a provider-specific contract, quota, billing or abuse controls. Successful suggestions remain editable; a timeout or error preserves the manual address. The public `nominatim.openstreetmap.org` endpoint is deliberately rejected; review the [Nominatim usage policy](https://operations.osmfoundation.org/policies/nominatim/) before selecting a service. Availability and coverage have not been verified in the deployment region.

Integration tests use isolated MongoDB and synthetic customers, proving ownership, conflicts, restart persistence and unconfigured-provider fallback. Unit tests mock the reverse provider; browser tests mock tiles and lookup failures. No live provider request or production customer information is used in tests.
