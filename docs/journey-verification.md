# Full journey verification status

Task 38 remains open. The application does not yet create orders or have persisted payment attempts, a callback/verification route, payment result pages, or a finished manual-order workflow. Consequently browse → cart → OTP → address/time → review → payment → result cannot be exercised as one end-to-end journey, and no successful payment or order placement is claimed. Delivery rules must be approved before real checkout quoting is enabled. See `order-review.md`, `delivery.md`, `manual-orders.md` and `payment-outcomes.md`.

The isolated integration suite covers individual domain and HTTP scenarios for guest cart merge, OTP lifecycle, customer profile and phone changes, ownership, media, catalog/product administration, contact settings, delivery quotes, order snapshots and authorization isolation. The optional real-browser integration in `tests/integration/catalog-browser.mjs` and `tests/integration/checkout-browser.mjs` uses isolated local MongoDB, synthetic records and desktop/mobile browsers; its checkout path ends at address selection with delivery disabled and reads a seeded order snapshot. It does not demonstrate a real OTP-to-payment journey. Foundation browser tests mock selected API responses and cover individual UI states; they are not a replacement for the complete production-backed journey.

On 2026-11-11 the pre-existing unit suite passed 30 tests, and the added `provider-isolation.test.mjs` plus payment contract/outcome tests passed seven targeted tests. They confirm the development SMS adapter rejects production and live payment configuration is rejected before provider calls. Payment contract tests inject a mock fetcher; they do not verify an actual provider sandbox or a persisted payment transition. No real SMS or provider request was sent.
