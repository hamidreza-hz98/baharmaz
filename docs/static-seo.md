# Static-page SEO

The protected `/admin/content` editor has title and description fields for the home, contact, FAQ, terms, about and product-list pages. Each page shows a text-only search/share preview and a completeness indicator. The indicator awards one point for a nonblank title of at most 160 UTF-16 code units and one for a nonblank description of at most 320, after trimming and Unicode NFKC normalization. These are the existing storage validation limits, not recommended search-result lengths or ranking criteria. The indicator does not predict ranking, indexing, traffic or how an external service will display a preview.

When a field is blank, the editor and public metadata use the same page-specific fallback independently for that field. Saving updates the document revision, revalidates affected routes, and renders the resolved title and description in the HTML title, description, Open Graph and Twitter summary tags. The preview illustrates text and the site-relative path; it does not promise an image or exact presentation by a third-party service. External platforms can cache previously retrieved tags. There is no new canonical-host or share-image configuration; `APP_ORIGIN` remains the separately configured security origin rather than an inferred public canonical URL.

Individual product and category titles and descriptions continue to be generated from catalog records, not these static-page settings. The products-list page uses the `products` static setting. All metadata is plain text and subject to the content settings validation and conflict handling described in `content-settings.md`.
