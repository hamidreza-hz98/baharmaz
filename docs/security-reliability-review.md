# Security and reliability review

## Scope and endpoint controls

Reviewed the App Router endpoints and shared identity, session, request, storage and indexing code. The following inventory describes implemented behavior, not a penetration test:

| Endpoint groups                                                                                                            | Access and controls                                                                                                                                                                                             |
| -------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/api/admin/{account,catalog,contact-submissions,content,customers,dashboard,delivery,manual-order,media,orders,products}` | Independent admin session; mutations require matching `APP_ORIGIN`, JSON and bounded bodies except binary media, which has its own content type, origin and byte limits.                                        |
| `/api/admin/login`, `/api/admin/logout`                                                                                    | Origin-protected login/logout; login uses scrypt and a shared fixed-window ceiling. Logout revokes the current admin session.                                                                                   |
| `/api/account`, `/api/account/logout`, `/api/account/orders`, order media                                                  | Customer session, owner-scoped queries and private no-store responses; account mutations require origin and JSON.                                                                                               |
| `/api/addresses`, `/api/addresses/map`, `/api/addresses/reverse`                                                           | Customer session, owner-scoped address CRUD, origin-protected mutations and globally limited reverse geocoding.                                                                                                 |
| `/api/delivery`, `/api/order-review`                                                                                       | Customer session and origin-protected bounded requests; quote validation checks owner, expiry and current state. These do not create an order.                                                                  |
| `/api/auth/otp`                                                                                                            | Origin-checked bounded JSON; shared and mobile challenge limits, expiry and single consumption; development logging only when explicitly enabled in development.                                                |
| `/api/cart`                                                                                                                | Guest bearer cookie or customer session; mutation requests require matching origin. Guest allocations have a shared fixed-window ceiling. GET currently creates guest carts and may merge after authentication. |
| `/api/contact`                                                                                                             | Origin-checked bounded JSON, validation and global/mobile rate limits; stores a message only.                                                                                                                   |
| `/api/catalog`, `/api/catalog/media`, `/api/content`, `/api/shop`, `/api/health`                                           | Public projections or generic health results. Public media requires an active public reference and validated WebP; health returns no connection details.                                                        |
| `/robots.txt`, `/sitemap.xml`                                                                                              | Public configured-origin indexing data; no private order, account or cart records.                                                                                                                              |

Cookies are HttpOnly, SameSite=Lax, scoped to `/`, and Secure in production. Server-side authorization is still required: cookie flags and noindex are not access controls. Admin/customer sessions are separate; customer mobile changes invalidate earlier sessions by version. User strings are rendered as text; JSON-LD escapes `<`. Regex search inputs are escaped and bounded. Most endpoints do not have individual per-user abuse limits; deploy a trusted edge limiter, request size/time limits and connection limits. Global fixed windows can be exhausted by one client and permit bursts at window boundaries. The new guest allocation ceiling is not a replacement for edge controls.

## Media, payment and recovery

Uploads are authenticated, bounded and signature-checked. Images are decoded and rewritten as WebP; MP4 container inspection does not fully decode or malware-scan video. Uploads buffer data in memory, so configure concurrency and memory limits. Public media is limited to referenced images; private media uses no-store and restrictive headers. See `media.md` for orphan handling and `information-pages.md` for public cache behavior.

Payment adapters and outcome transitions do not implement a persisted gateway callback, reconciliation or transactional order creation. Idempotent payment fulfillment, callback replay, amount reconciliation and backup/restore of real payment records cannot currently be verified; keep live payments disabled until tasks 22–24 are complete. Manual-order creation is also disabled. Do not interpret a callback or administrator transfer assertion as verified payment.

Index creation is explicit and documented in the identity, cart, delivery, contact, catalog and order guides; back up before applying indexes and never use destructive index synchronization by default. Readiness reports only database connectivity, not index correctness, backup health or provider readiness. Establish encrypted off-host backups that include the `lamsechi` database and both GridFS collections, least-privilege access, retention and alerts. A synthetic cold standalone copy/restore and repeat-index test now passes, but a production-topology backup/restore exercise and recovery-time objective have not been verified; test the selected production backup method in isolation before release without printing customer data or credentials. Do not run restore commands against production by default.

Production SMS is not configured, the development fake can log phone numbers and OTPs when explicitly enabled, and application/proxy/platform logs and error reporting must be configured not to record credentials, cookies, OTPs, messages, addresses, payment references or request bodies. Browser-visible map tile URLs must contain no secret credentials. The application does not have a full CSP rollout, centralized audit monitoring, per-principal controls for every endpoint, production secret rotation or a documented incident-response exercise. Review these before release. Existing documentation in `otp.md`, `admin-authentication.md`, `addresses.md`, `indexing.md` and `database.md` contains further constraints.

## Verification and remaining scope

The isolated integration suite exercises role isolation, session expiry/revocation, origin rejection, OTP limits and replay, ownership, upload checks, contact throttling, order read isolation, quote staleness and synthetic database restart. The review adds a matrix for anonymous/customer access to admin reads and a guest allocation throttle check. A later cold-copy test verified isolated standalone restoration of a synthetic record, GridFS bytes and indexes; it does not validate the eventual production backup method. The suite does not prove production reverse-proxy configuration, real payment idempotency, malware resistance or load capacity. Task 36 remains open until production-like recovery and blocked real payment/idempotency checks are completed and reviewed.
