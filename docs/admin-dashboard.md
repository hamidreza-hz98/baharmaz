# Admin dashboard

The dashboard is protected by the admin session. Recent orders are sorted by `placedAt` and `_id`, newest first; each status filter shows at most ten. View-all uses 20-row pages. Status values follow the provisional customer order read model.

Sales mean the sum of `totals.paidRials` from order snapshots marked `payment.status = verified` with a valid verification timestamp, grouped by verification time in `Asia/Tehran`. The amount is the paid total after discounts and including shipping. Cancellations do not remove a verified payment. The current model has no refund ledger, so these figures are not net revenue and cannot account for refunds, partial refunds or chargebacks. Missing or invalid verified payment data makes the metrics fail rather than appear as zero. Integer rials are summed, overflow is rejected and amounts are displayed as whole tomans. No currency conversion is inferred.

Day starts at Tehran midnight and groups by hour; week is today and the preceding six Tehran civil days; month is today and the preceding 29 civil days; year is the current and preceding eleven Gregorian calendar months, grouped by month. Only buckets with verified payments are shown, including a paid zero where present. Best customers are the five highest all-time verified paid totals, grouped by customer ID, using the latest order's snapshot name. Product ranking counts quantities in verified paid orders across all time, grouped by snapshot title, so identically named products are combined. This is explicitly labelled as names, not stable product identity. Ties use the identifier or name for deterministic ordering.

The order collection and statuses are provisional: task 22 has not implemented real transactional order creation, and snapshots do not enforce immutability or carry stable product identifiers. The create-order action is disabled until its workflow exists. Reconcile reporting with the actual order, payment and refund lifecycle before production and do not treat synthetic test data as real sales. Task 27 remains open until creation and product-level ranking can be verified end to end.

Back up the database before running `npm run db:order:indexes` to create the added recent-order and verified-payment lookup indexes. Rankings still scan verified order snapshots and should be reviewed for performance as the order volume grows.
