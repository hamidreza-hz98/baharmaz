# Customer profile and orders

`/account` is the authenticated profile entry point. The responsive profile navigation links to existing personal-information and address-management pages. Customer logout requires the customer session and matching `APP_ORIGIN`, revokes that current server session, clears its cookie and clears the tab's temporary checkout selections. It does not revoke other customer sessions or the independent admin session. A failed logout leaves the customer on the page with a retryable error.

The default orders area reads customer-owned records from the `orders` collection, supports status filters and shows order details and private snapshot images. It never joins current product or address data into historical snapshots. Only records with verified payment status and a valid verification time are presented as paid. Snapshot images are available only through an owner-checked, no-store route. The status vocabulary and read schema are provisional and must be reconciled with the order-creation implementation in task 22; do not seed real orders manually or treat this read model as an order-creation workflow. Back up the target database before running `npm run db:order:indexes`; duplicate order codes require manual review.

Transactional order creation and immutable snapshot enforcement remain unimplemented. Task 25 must remain open until real orders can be created and the complete order lifecycle and historical immutability have been verified. Customer address CRUD and personal-information tests are documented separately in `docs/addresses.md` and `docs/testing.md`.
