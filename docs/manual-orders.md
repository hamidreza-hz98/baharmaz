# Manual order preview

An authenticated administrator can open `/admin/orders/new` from the dashboard or order list. The form selects an existing customer, that customer's address, available products and quantities, a configured delivery date and slot, and one of three card-to-card transfer descriptions. Search results show the first 20 matches; refine the search to find another customer or product. No SMS, bank transfer or gateway request is sent.

The protected preview API reloads products and their current integer-rial prices, checks address ownership and the active delivery policy, recalculates discount and shipping, and returns a non-binding total. Invalid items, missing configuration, missing coordinates, overlapping or out-of-area zones and unavailable slots fail without inventing a fee. The transfer description is only preview data: `reported` means the transfer was reported and `admin_confirmed` means an admin assertion, not gateway verification. Neither is persisted as payment or counted as verified sales. The preview is not an order, reservation, quote, or guarantee of unchanged prices or delivery availability.

**Order submission is not implemented.** Do not treat a preview as a created order. Task 30 remains open until a transaction-capable MongoDB deployment and the order-creation contract are implemented, source data and delivery rules are atomically revalidated, an idempotency key prevents duplicate creation, immutable snapshots and the creation audit are stored, card-to-card assertions are persisted separately from gateway verification, and the result is verified in admin and customer views. Task 22 and approved delivery configuration are upstream dependencies; see `order-review.md` and `delivery.md`.
