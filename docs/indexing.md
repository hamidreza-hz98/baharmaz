# Public indexing and structured data

Set `APP_ORIGIN` to the exact public origin with no path, query, fragment or credentials. Production requires HTTPS. This is also the origin used for mutation protection; configure reverse proxies accordingly. Static public pages and existing products and categories emit absolute canonical URLs using this origin, independent of incoming Host headers. Missing or archived catalog entries emit no canonical and are marked noindex. If `APP_ORIGIN` is missing or invalid, public metadata is marked noindex, `robots.txt` disallows crawling and the sitemap returns 503; configure the origin rather than publishing guessed URLs.

`/robots.txt` links to `/sitemap.xml` and disallows API crawling. Private account, checkout, cart and admin pages emit `noindex, nofollow` and are excluded from the sitemap. Private pages are not disallowed by robots because a crawler needs to fetch a page to see its noindex directive; authentication remains the actual access boundary. Search engines can retain already indexed URLs until recrawled, and robots/noindex are not a substitute for authorization.

The dynamic sitemap includes public static pages, unarchived categories and unarchived products with an unarchived category, including unavailable products. It uses only the configured origin and public slugs, and fails with 503 rather than silently truncating if the database is unavailable or the 50,000-URL single-sitemap limit is exceeded. At that scale, implement a sitemap index and paginated shards before raising the limit. No user, cart, order or administrative data is included.

The homepage includes a `WebSite` JSON-LD object and product detail pages include a minimal `Product` object with public name, URL and optional excerpt. Less-than characters are escaped when serializing. No price, offers, inventory, review, brand or shipping claims are invented; the current checkout and currency policies are not yet fully approved. This minimal markup does not promise rich-result eligibility. Validate the deployed pages using search-engine inspection tools after configuring the production origin. Existing product and category title/description generation remains automatic; static settings are covered in `static-seo.md`.

The root loading boundary can cause missing product/category pages to stream a 200 response before their not-found content and noindex tag; see `public-catalog.md`. A true 404 remains outstanding for that separate catalog task and should be addressed before release.
