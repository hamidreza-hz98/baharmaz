# Aqaye Pardakht sandbox checkout

The checkout uses Aqaye Pardakht's sandbox only. Its [official API documentation](https://aqayepardakht.ir/api/) specifies the `sandbox` PIN, sandbox payment page, toman amounts, and server-side verification. Live payment remains disabled. No card details are accepted or stored by the shop.

Set `AQAYE_MODE=sandbox`, `AQAYE_PIN=sandbox`, and `AQAYE_CALLBACK_URL` to the application callback base ending in `/api/payments/aqaye/callback`. The configured callback must use HTTPS, except for localhost HTTP when `NODE_ENV=development`. The app appends an unguessable per-attempt reference. The local development settings use `http://localhost:3000/api/payments/aqaye/callback`. When deployed, the callback domain must be reachable from the customer's browser and meet the provider's requirements.

Submitting revalidates the server-owned delivery quote and cart, stores an immutable test snapshot in `sandbox_checkouts`, and initiates the provider request once per quote. An ambiguous initiation or verification response remains unconfirmed and is not automatically retried. The callback accepts GET and form POST (the provider sandbox returned a form POST during the local test), matches the callback reference and transaction, and verifies the server-stored amount with the provider. Duplicate submissions and callbacks cannot create a second payment or downgrade a verified result. The cart is cleared after verified sandbox success only if its revision has not changed since submission.

Verified sandbox checkouts create clearly marked test orders in the customer and admin order workflows so their details and status changes can be tested. These are excluded from real dashboard and customer sales metrics, and do not trigger fulfillment or real payment processing. Failed or unresolved attempts remain separate; a failed sandbox payment leaves the cart intact. For a stored sandbox transaction, the authenticated result page can reconcile an uncertain outcome with the provider; its already-verified response confirms success. Other uncertain responses remain unconfirmed.

Checks: `node --conditions=react-server --test tests/payment.test.mjs tests/payment-outcome.test.mjs`. `tests/integration/sandbox-payment-case.mjs` exercises replay, concurrent submission, ownership, failure, and verification with an isolated test database and mocked provider; opt in to provider requests with `SANDBOX_REAL_SMOKE=1`. `tests/integration/sandbox-checkout-browser.mjs` requires `SANDBOX_BROWSER_SMOKE=1`, the local development server and local MongoDB; it creates and removes specifically identified synthetic records. On 17 November 2026 both sandbox choices were exercised with synthetic data in a browser and returned to localhost. Never use real customer data in provider tests.
